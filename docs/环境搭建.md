# AstraTune 环境搭建

跨平台入口以 Docker Compose 为准。本仓另有 **两套独立评测 Docker**（勿与 AstraTune 栈合并）：BIRD-CRITIC `benchmark/evaluation`，以及慢 SQL 专项 **Diff-SQL**（根目录 submodule `Diff-SQL/`）。

克隆含 submodule 时：

```bash
git clone --recurse-submodules <本仓 URL>
# 或已有工作区：
git submodule update --init Diff-SQL
```

## 1. Python 依赖

```bash
conda create -n at python=3.10
conda activate at
pip install uv
uv pip install -r requirements.txt
```

LLM 调用需设置 **`OPENAI_API_KEY`** 或 **`OPENAI_API_KEYS`**（多个用 `;` 分隔）。当前 `config/agents.json`：`base_url` 多为 ChatAnywhere（可换 DeepSeek）；`batch.llm_key_mode=single`，`llm_workers=16`（loader fallback 仍为 `auto`）。与沙箱 `--workers` 独立。超时：诊断 `response_timeout=120s`，Generate/Verify `360s`，`max_attempts=4`；批跑单题 `instance_timeout_s=2400`（subprocess 强杀）。

## 2. 启动数据库栈（推荐）

将 BIRD-CRITIC 的 PostgreSQL dump 放到 `benchmark_data/dumps/postgresql/`；MySQL dump 放到 `benchmark_data/dumps/mysql/`。AstraTune `docker/docker-compose.yml` 已挂载这两处（容器内仍为 `postgre_table_dumps` / `mysql_table_dumps`）。

```bash
cd docker
docker compose --env-file stack.defaults.env up -d --build
```

服务：


| 服务              | 端口   | 说明                                                               |
| --------------- | ---- | ---------------------------------------------------------------- |
| `pg_target`     | 5432 | PG 目标库（含 financial 等），用户 `root` / `123123`                       |
| `pg_sandbox`    | 5433 | PG 沙箱库，用户 `postgres` / `astratune_sandbox`                       |
| `mysql_target`  | 3306 | MySQL 目标库，用户 `root` / `123123`（首次初始化较慢）                          |
| `mysql_sandbox` | 3307 | MySQL 沙箱库，用户 `root` / `astratune_sandbox`，库名 `astratune_sandbox` |
| `target_db_api` | 8010 | PG 目标库只读 HTTP API                                                |


停止：

```bash
cd docker
docker compose --env-file stack.defaults.env down
```

## 3. 配置文件

- `config/agents.json`：诊断 / 优化 Agent 的 LLM、`max_iter`、`max_rounds` 等
- `config/sandbox.json`：按方言分段（`postgresql` / `mysql`）的沙箱连接与采样参数
- `config/target_db.json`：按方言分段的目标库连接（`database` 可被 CLI `--db-id` 覆盖）

CLI 用 `--dialect postgresql|mysql` 选取对应段。

## 4. 跑通单条推理

唯一入口 `scripts/infer.py`（`--function` × `--mode`）：

```bash
cd scripts
python infer.py --db-id financial --sql "SELECT t.trans_id, t.account_id, t.date, t.type, t.amount FROM trans t JOIN account a ON t.account_id = a.account_id WHERE a.district_id = 18 AND t.bank = 'AB' AND t.type IN ('PRIJEM', 'VYDAJ');" --user-prompt "We have a large transaction table..." --mode diag+opt --function general
```

MySQL：

```bash
cd scripts
python infer.py --dialect mysql --db-id financial --sql "SELECT * FROM account LIMIT 5;" --user-prompt "smoke" --mode diag_only
```

更多用例见 `data/测试数据.md`。BIRD / Effi 评测对接见 `docs/评测对接.md`。

## 5. Diff-SQL / Effi-SQL（性能评测 · 已完成）

根目录 submodule **`Diff-SQL/`**（[L-nshpp/Diff-SQL](https://github.com/L-nshpp/Diff-SQL)）：面向 **SQL 效率 / 慢查询** 的专门评测集（Effi-SQL），**自带 Docker 与评测脚本**，与本节 §2 的 AstraTune 栈、以及 BIRD 官方评测容器 **保持独立，勿合并 compose**。

**正式全量成绩**：match **91.7%** / R-VES **0.7642** / Coverage@2x **55.67%** / GMS **4.0814** — 见 [`docs/effi300评测报告.md`](effi300评测报告.md)。

题面：`benchmark_data/effi/input/`；dumps：`benchmark_data/dumps/bird-interact/`、`benchmark_data/tpch-3g/raw/`（Diff-SQL compose 已挂载）。小库 `:7001`，TPC-H `:5438`。直连配置：`config/effi_db.json`（含 `statement_timeout_ms` / `max_fetch_rows`）。

```bash
# Diff-SQL/ 下（Git Bash / WSL；Windows 亦可 docker compose 直启）
SMALLDB_ONLY=1 bash scripts/db_up.sh
# 仅小库冒烟也可用：
# docker compose -f docker/compose/smalldb.yml up -d --build postgresql_small

# 仓库根：推理 → 官方 end2end
python scripts/infer.py --benchmark effi --id 229 --function efficiency --mode diag+opt --output outputs/effi_one.json
python scripts/run_effi_sql.py --ids 229 --mode diag+opt --output outputs/effi_pred.jsonl
# 本机 bash 若为 WSL 启动器，run_effi_eval 可能挂起；可改 docker exec so_eval_env 直跑（见评测报告）
python scripts/run_effi_eval.py --pred outputs/effi_pred.jsonl
```

| 项 | 说明 |
| ---- | ---- |
| 状态 | **全量正式评测已完成**（300 题） |
| 用途 | Effi-SQL 性能评测（match_rate + R-VES；榜单另计 Coverage@2x / GMS） |
| 题面 | `benchmark_data/effi/input/effi-sql-pg.jsonl`（亦可 Diff-SQL 副本） |
| DB 资产 | Interact dumps → `benchmark_data/dumps/bird-interact/`；TPC-H raw → `benchmark_data/tpch-3g/raw/` |
| 启停评测库 | `Diff-SQL/scripts/db_up.sh` / `db_down.sh` |
| 跑评测 | `EVAL_SQL_MODE=end2end` + `scripts/run_effi_eval.py`（封装 Diff-SQL `run_eval.sh`） |
| 批跑 | 默认 `--isolate subprocess`；同库串行、跨库并行；见 `run_effi_sql.py` / `run_effi_worker.py` |

细节见 `docs/评测对接.md` §4、`Diff-SQL/README.md`。

## 6. WebUI（P2）

规格：[`docs/spec_webui.md`](spec_webui.md)。

```bash
conda activate at
# 仅需 AstraTune docker 栈（§2）；不要为了 WebUI 去起 Diff-SQL / BIRD 评测容器
# 前端已构建则可直接：
python at_webui.py
# 浏览器打开 http://127.0.0.1:8080

# 开发热更新：另开终端
#   set AT_WEBUI_DEV=1
#   python at_webui.py
#   cd webui/frontend && npm run dev
```

WebUI 走目标库采样沙箱，与 `infer.py` 相同；配置改动写入 `data/webui/webui.sqlite` overlay，**不写回** `config/*.json`。无登录。并行默认 2、上限 4。

开发：`AT_WEBUI_DEV=1` 时后端不托管静态资源，前端 `webui/frontend` 下 `npm run dev`（代理 `/api`）。
