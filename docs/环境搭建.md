# AstraTune 环境搭建

跨平台入口以 Docker Compose 为准。本仓另有 **两套独立评测 Docker**（勿与 AstraTune 栈合并）：BIRD-CRITIC `benchmark/evaluation`，以及慢 SQL 专项 **Diff-SQL**（根目录 submodule `Diff-SQL/`）。

克隆含 submodule 时：

```bash
git clone --recurse-submodules <本仓 URL>
# 或已有工作区：
git submodule update --init Diff-SQL
```

## 1. Python 依赖

```bash
conda create -n at python=3.10
conda activate at
pip install uv
uv pip install -r requirements.txt
```

LLM 调用需设置 **`OPENAI_API_KEY`** 或 **`OPENAI_API_KEYS`**（多个用 `;` 分隔）。当前 `config/agents.json`：`base_url` 多为 ChatAnywhere（可换 DeepSeek）；`batch.llm_key_mode=auto`，`llm_workers=4`。与沙箱 `--workers` 独立。超时：诊断 `response_timeout=120s`，Generate/Verify `360s`，`max_attempts=4`；批跑单题 `instance_timeout_s=2400`（subprocess 强杀）。

## 2. 启动数据库栈（推荐）

将 BIRD-CRITIC 的 PostgreSQL dump 放到 `benchmark_data/dumps/postgresql/`；MySQL dump 放到 `benchmark_data/dumps/mysql/`。AstraTune `docker/docker-compose.yml` 已挂载这两处（容器内仍为 `postgre_table_dumps` / `mysql_table_dumps`）。

```bash
cd docker
docker compose --env-file stack.defaults.env up -d --build
```

服务：


| 服务              | 端口   | 说明                                                               |
| --------------- | ---- | ---------------------------------------------------------------- |
| `pg_target`     | 5432 | PG 目标库（含 financial 等），用户 `root` / `123123`                       |
| `pg_sandbox`    | 5433 | PG 沙箱库，用户 `postgres` / `astratune_sandbox`                       |
| `mysql_target`  | 3306 | MySQL 目标库，用户 `root` / `123123`（首次初始化较慢）                          |
| `mysql_sandbox` | 3307 | MySQL 沙箱库，用户 `root` / `astratune_sandbox`，库名 `astratune_sandbox` |
| `target_db_api` | 8010 | PG 目标库只读 HTTP API                                                |


停止：

```bash
cd docker
docker compose --env-file stack.defaults.env down
```

## 3. 配置文件

- `config/agents.json`：诊断 / 优化 Agent 的 LLM、`max_iter`、`max_rounds` 等
- `config/sandbox.json`：按方言分段（`postgresql` / `mysql`）的沙箱连接与采样参数
- `config/target_db.json`：按方言分段的目标库连接（`database` 可被 CLI `--db-id` 覆盖）

CLI 用 `--dialect postgresql|mysql` 选取对应段。

## 4. 跑通单条诊断

PostgreSQL：

```bash
cd scripts
python diag.py --db-id financial --sql "SELECT t.trans_id, t.account_id, t.date, t.type, t.amount FROM trans t JOIN account a ON t.account_id = a.account_id WHERE a.district_id = 18 AND t.bank = 'AB' AND t.type IN ('PRIJEM', 'VYDAJ');" --user-prompt "We have a large transaction table..."
```

MySQL：

```bash
cd scripts
python diag.py --dialect mysql --db-id financial --sql "SELECT * FROM account LIMIT 5;" --user-prompt "smoke"
```

更多用例见 `data/测试数据.md`。成功时输出应包含 `【诊断结论】`。

BIRD-CRITIC 评测对接见 `docs/评测对接.md`。

## 5. Diff-SQL / Effi-SQL（下一步：性能评测）

根目录 submodule **`Diff-SQL/`**（[L-nshpp/Diff-SQL](https://github.com/L-nshpp/Diff-SQL)）：面向 **SQL 效率 / 慢查询** 的专门评测集（Effi-SQL），**自带 Docker 与评测脚本**，与本节 §2 的 AstraTune 栈、以及 BIRD 官方评测容器 **保持独立，勿合并 compose**。

| 项 | 说明 |
| ---- | ---- |
| 用途 | 后续慢 SQL 专项评测（计划中；本轮仅挂仓与文档） |
| 题面 | HuggingFace `birdsql/Effi-SQL` → 落到 `Diff-SQL/data/benchmark/effi-sql/` |
| DB 资产 | BIRD-Interact scale dumps、TPC-H 3G raw → `Diff-SQL/data/databases/`（占位与说明见该仓 README） |
| 启停评测库 | `Diff-SQL/scripts/db_up.sh` / `db_down.sh`（内部用 `Diff-SQL/docker/compose/`） |
| 跑评测 | `EVAL_SQL_MODE=patch|end2end` + `Diff-SQL/scripts/run_eval.sh`；汇总 `aggregate_eval.sh` |

依赖与用法以 **`Diff-SQL/README.md`** 为准；AstraTune 侧对接（预测字段映射、批跑入口）排在 PG530 机制复跑之后，见 `docs/过程文档.md` §1.4 / §3.2 / §8.2。
