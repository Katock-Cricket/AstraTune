## 1. 项目背景与目标

### 1.1 研究背景

AstraTune 是一种基于大模型与多智能体协同的数据库慢查询诊断与优化方法。研究内容以卫星互联网为应用场景，但实际实现面向更广泛的 SQL 问题解决，最终以 BIRD-CRITIC Benchmark 作为实验验证基准。

### 1.2 总目标（GOAL）

1. **诊断智能体**：ReAct + 沙箱 — **已调通**
2. **修复多智能体**：Generate–Verify（无 Reflect）— **已完成**
3. **BIRD-CRITIC 实验验证**：Flash 200 工程 + 准确率 — **≥50% 已达标（51.00%）**；val28 门禁 **71.43%** 已过；PG 530 / Open-MySQL 全量延后
4. **WebUI**：单条全流程演示 — **未实现（P2）**

### 1.3 已确认的需求调整

| 原定模块 | 决策 | 说明 |
| ---- | ---- | ---- |
| 微调数据集 / Qwen3-32B | **砍掉** | 基座 API（当前 `deepseek-v4-flash`） |
| RAG / 经验库 | **砍掉** | 勿恢复 |
| Reflect / 知识沉淀 | **已删除** | 失败由 Verify `failure_reasons` 回灌 Generate |
| 达梦（DM） | **冻结** | `NotImplementedError` |
| 卫星互联网领域限定 | **泛化** | 通用 SQL |
| Verify DDL/DML 硬拦 | **已取消** | 安全靠沙箱隔离 |

### 1.4 评测范围确认

- **方言**：PostgreSQL + MySQL（均需支持）
- **当前验收集**：BIRD-CRITIC Flash 200（PG）— **已评测**
- **延后**：PG 全量 530 + Open-MySQL ~100
- **Category**：Query / Management / Personalization / Efficiency
- **评测机制**：官方 `benchmark/evaluation/` wrapper

## 6. 环境搭建（摘要）

完整步骤见 `docs/环境搭建.md`。

```bash
conda activate at
cd docker && docker compose --env-file stack.defaults.env up -d --build
```

配置：`config/agents.json`（`llm_key_mode=auto`，`llm_workers=4`，`instance_timeout_s=2400`）。

### Flash 200 复现

```bash
python scripts/run_bird_critic.py \
  --schema benchmark/baseline/data/flash_schema.jsonl \
  --input benchmark/baseline/data/flash/flash-00000-of-00001.jsonl \
  --dialect postgresql --output outputs/flash200_pred.jsonl \
  --resume --workers 4 --mode diag+opt --force-batch

python scripts/merge_pred_with_sol.py \
  --pred outputs/flash200_pred.jsonl \
  --sol benchmark/evaluation/flash_sol/bird-critic-1.0-flash_w_sol.jsonl \
  --output outputs/flash200_eval_ready.jsonl --require-pred

python scripts/run_official_eval.py \
  --dialect postgresql --jsonl outputs/flash200_eval_ready.jsonl --num_threads 2
```

进度：`python scripts/_flash200_status.py`；体积过大时：`python scripts/slim_pred_jsonl.py --path outputs/flash200_pred.jsonl`。

## 9. 开发注意事项

1. **LLM**：`OPENAI_API_KEYS`（`;`）或 `OPENAI_API_KEY`；`llm_key_mode=auto`；与 `--workers` 沙箱槽独立。
2. **批跑**：默认 `--isolate subprocess`；勿改回 inproc 跑全量。
3. **推理不喂 sol**；merge 阶段才合入。
4. **评测 `--limit`**：省略=全量；见 `docs/评测对接.md` §2.1。
5. **Docker 磁盘**：跑批前确认 D: ≥30–50GB。
6. **StreamHandler**：批跑模式截断工具/LLM 日志，避免管道撑死。
