# AstraTune ↔ BIRD-CRITIC / Effi-SQL 评测对接

推理产出 `pred_sqls` 后，再与本地 gold `*_sol` 合并，调用官方 wrapper（BIRD）；Effi 走 Diff-SQL end2end（§4）。

题面 / schema / sol / table dumps 在仓库根 **`benchmark_data/`**；官方 wrapper 源码仍在 `benchmark/evaluation/src`。

**当前主跑批**：**PG 530**（§3）。正式成绩见 `docs/pg530评测报告.md`。  
**Effi-SQL**：**全量评测已完成**（§4）；正式成绩见 `docs/effi300评测报告.md`。

## 1. 合并

PG：

```bash
python scripts/merge_pred_with_sol.py \
  --pred outputs/pg530_pred.jsonl \
  --sol benchmark_data/sol/pg_sol/pg_sol.jsonl \
  --output outputs/pg530_eval_ready.jsonl \
  --require-pred
```

MySQL（Open，延后）：

```bash
python scripts/merge_pred_with_sol.py \
  --pred outputs/mysql_pred.jsonl \
  --sol benchmark_data/sol/open_sol/open_sol.jsonl \
  --output outputs/mysql_eval_ready.jsonl \
  --require-pred
```

合并键：`instance_id`。推理阶段不得读取 `sol_sql`；仅本脚本合并。

注意：若本地 `pg_sol.jsonl` / `open_sol.jsonl` 与题面 `instance_id` 不对齐，可用含 gold 的完整输入（如 `data/eff_subset.jsonl`）作为 `--sol` 源，或先校验同 id 的 `db_id`/`category` 再合并。

## 2. 官方评测（宿主机连 AstraTune target）

默认路径：评测脚本连 `127.0.0.1:5432`（PG）或 `127.0.0.1:3306`（MySQL），账号 `root` / `123123`，与 AstraTune `pg_target` / `mysql_target` 对齐。  
主机可用环境变量覆盖：`BIRD_PG_HOST` / `BIRD_MYSQL_HOST`（或统一 `BIRD_DB_HOST`）。

### PostgreSQL

```bash
cd benchmark/evaluation/src
python wrapper_evaluation_postgresql.py \
  --jsonl_file ../../../outputs/pg530_eval_ready.jsonl \
  --mode pred \
  --limit 1 \
  --num_threads 1
```

### MySQL

```bash
cd benchmark/evaluation/src
python wrapper_evaluation_mysql.py \
  --jsonl_file ../../../outputs/mysql_eval_ready.jsonl \
  --mode pred \
  --limit 1 \
  --num_threads 1 \
  --mysql_password 123123
```

也可使用薄封装：

```bash
# 全量（推荐）：省略 --limit，封装会按 JSONL 行数评完
python scripts/run_official_eval.py --dialect postgresql --jsonl outputs/pg530_eval_ready.jsonl --num_threads 2
python scripts/run_official_eval.py --dialect mysql --jsonl outputs/mysql_eval_ready.jsonl --num_threads 2

# 冒烟：只评前 N 条
python scripts/run_official_eval.py --dialect postgresql --jsonl outputs/pg530_eval_ready.jsonl --limit 1
```

### 2.1 `--limit`（必读，易踩坑）

| 调用方                            | `--limit` 含义                | 默认                  |
| ------------------------------ | --------------------------- | ------------------- |
| `scripts/run_official_eval.py` | 评测条数上限；**省略 = JSONL 全部非空行** | 省略=全量（旧默认曾是 `1`，已改） |
| `wrapper_evaluation_*.py`      | 同上；`None`/省略 = 不切片，评文件内全部   | 省略=全量               |

**固化约定**：

1. 报官方 Overall Accuracy / 写复盘数字前，确认日志里有 `Official eval scope: 全量 (N)` 或 `N/N`，且 `Total instances: N` 与 pred 条数一致。
2. **PG 530**：`N` 必须等于 **530**。
3. 仅调试连通性时才用 `--limit 1`；此时报告准确率**不得**当作集合成绩。
4. 直接调官方 wrapper 时同样：`--limit 1` 只评 1 题；全量请**不要传** `--limit`，或显式传集合大小。

## 3. PG 530（现行主跑批）

数据集：`bird-critic-1.0-postgresql`（530 条，PostgreSQL）。`instance_id` 形如 `PostgreSQL_0` … `PostgreSQL_529`。

正式成绩：**51.13%（271/530）** — `docs/pg530评测报告.md`。

### 3.1 数据文件

| 用途 | 路径 | 说明 |
| ---- | ---- | ---- |
| Schema | `benchmark_data/schema/post_schema.jsonl` | 530 行；含 `preprocess_schema` |
| 题面 input | `benchmark_data/input/post/pg-00000-of-00001.jsonl` | **530 行**；含 `issue_sql` / `query` / `category` 等 |
| Gold sol | `benchmark_data/sol/pg_sol/pg_sol.jsonl` | 530 行；含 `sol_sql` + `test_cases` |

题面须 **schema ⊕ input**（仅 schema 无 `issue_sql`）。若本地尚无 `post/` 目录，从 HuggingFace 拉取题面（**勿**把 `sol_sql` / `test_cases` 写入推理输入）：

  "https://huggingface.co/datasets/birdsql/bird-critic-1.0-postgresql/resolve/main/data/pg-00000-of-00001.jsonl"

### 3.3 推理

```bash
python scripts/run_bird_critic.py \
  --schema benchmark_data/schema/post_schema.jsonl \
  --input benchmark_data/input/post/pg-00000-of-00001.jsonl \
  --dialect postgresql --output outputs/pg530_pred.jsonl \
  --resume --workers 4 --mode diag+opt --force-batch
```

- 默认 `--isolate subprocess`；沙箱 `--workers` 与 LLM 池独立；LLM 见 `config/agents.json`（现行 `llm_workers=16`，`llm_key_mode=single`）。
- `--resume`：已有 `pred_sqls` 的题跳过；中断可续跑。
- 冒烟：`--ids PostgreSQL_0,PostgreSQL_37`（Eff 子集见 `data/eff_subset.jsonl`）。
- 跑批前：`docker compose up -d`；D: 保留 ≥30–50GB（大批量后 vhdx 易虚胖，见 `AGENTS.md`）。

进度粗查：

```bash
python -c "import json;from pathlib import Path;p=Path('outputs/pg530_pred.jsonl');by={};
import sys
[by.update({json.loads(l).get('instance_id'):1}) for l in p.open(encoding='utf-8') if l.strip()] if p.is_file() else None
print('unique=',len(by),'size_mb=',round(p.stat().st_size/1048576,1) if p.is_file() else 0)"
```

体积过大：`python scripts/slim_pred_jsonl.py --path outputs/pg530_pred.jsonl`。

## 4. Effi-SQL 性能评测（**已完成**）

数据：`benchmark_data/effi/input/effi-sql-pg.jsonl`；dumps：`benchmark_data/dumps/bird-interact/`、`benchmark_data/tpch-3g/raw/`。  
Diff-SQL compose 已挂载上述路径（`:7001` 小库 / `:5438` TPC-H）。直连：`config/effi_db.json`。

```bash
# 1) Diff-SQL DB（在 Diff-SQL/ 下，Git Bash / WSL）
bash scripts/db_up.sh

# 2) 推理（单题）
python scripts/infer.py --benchmark effi --id 1 --function efficiency --mode diag+opt --output outputs/effi_one.json

# 或批跑（默认 --isolate subprocess；同库串行、跨库并行；勿用 inproc 多开）
python scripts/run_effi_sql.py --ids 1,2,229,230 --mode diag+opt --workers 4 \
  --output outputs/effi_pred.jsonl --log-file outputs/effi_pred.log

# 中断续跑 / 只重跑未 Verify 通过的
python scripts/run_effi_sql.py --ids 1,2,229,230 --resume --rerun-nonok --workers 6 \
  --output outputs/effi_pred.jsonl

# 全量示例
python scripts/run_effi_sql.py --mode diag+opt --workers 4 --resume \
  --output outputs/effi300_pred.jsonl --log-file outputs/effi300_pred.log

# 3) 官方 end2end 评测
python scripts/run_effi_eval.py --pred outputs/effi300_pred.jsonl
# 若本机 bash 为 WSL 启动器易挂：改 docker exec so_eval_env 直跑（见报告备注）
```

指标：match_rate + R-VES（Diff-SQL `_aggregate_metrics`）；榜单另计 **Coverage@2x** / **GMS**（同产物回放）。与 AstraTune / BIRD Docker **三套独立**。  

**正式全量报告（评测已完成）**：`docs/effi300评测报告.md`（300 题 match 91.7% / R-VES 0.7642 / Coverage@2x 55.67% / GMS 4.0814）。  
小规模对照：`docs/effi16评测报告.md`（16 题 match 93.8% / R-VES 0.7500）。
