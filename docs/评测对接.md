# AstraTune ↔ BIRD-CRITIC 评测对接

推理产出 `pred_sqls` 后，再与本地 gold `*_sol` 合并，调用官方 wrapper。

## 1. 合并

PG：

```bash
python scripts/merge_pred_with_sol.py \
  --pred outputs/pg_pred.jsonl \
  --sol benchmark/evaluation/pg_sol/pg_sol.jsonl \
  --output outputs/pg_eval_ready.jsonl \
  --require-pred
```

MySQL（Open）：

```bash
python scripts/merge_pred_with_sol.py \
  --pred outputs/mysql_pred.jsonl \
  --sol benchmark/evaluation/open_sol/open_sol.jsonl \
  --output outputs/mysql_eval_ready.jsonl \
  --require-pred
```

合并键：`instance_id`。推理阶段不得读取 `sol_sql`；仅本脚本合并。

注意：若本地 `pg_sol.jsonl` / `open_sol.jsonl` 与题面 `instance_id` 不对齐，可用含 gold 的完整输入（如 `data/eff_subset.jsonl`）作为 `--sol` 源，或先校验同 id 的 `db_id`/`category` 再合并。

## 2. 官方评测（宿主机连 AstraTune target）

默认路径：评测脚本连 `127.0.0.1:5432`（PG）或 `127.0.0.1:3306`（MySQL），账号 `root` / `123123`，与 AstraTune `pg_target` / `mysql_target` 对齐。  
主机可用环境变量覆盖：`BIRD_PG_HOST` / `BIRD_MYSQL_HOST`（或统一 `BIRD_DB_HOST`）。

### PostgreSQL

```bash
cd benchmark/evaluation/src
python wrapper_evaluation_postgresql.py \
  --jsonl_file ../../../outputs/pg_eval_ready.jsonl \
  --mode pred \
  --limit 1 \
  --num_threads 1
```



### MySQL

```bash
cd benchmark/evaluation/src
python wrapper_evaluation_mysql.py \
  --jsonl_file ../../../outputs/mysql_eval_ready.jsonl \
  --mode pred \
  --limit 1 \
  --num_threads 1 \
  --mysql_password 123123
```

也可使用薄封装：

```bash
# 全量（推荐）：省略 --limit，封装会按 JSONL 行数评完
python scripts/run_official_eval.py --dialect postgresql --jsonl outputs/pg_eval_ready.jsonl --num_threads 2
python scripts/run_official_eval.py --dialect mysql --jsonl outputs/mysql_eval_ready.jsonl --num_threads 2

# 冒烟：只评前 N 条
python scripts/run_official_eval.py --dialect postgresql --jsonl outputs/pg_eval_ready.jsonl --limit 1
```



### 2.1 `--limit`（必读，易踩坑）


| 调用方                            | `--limit` 含义                | 默认                  |
| ------------------------------ | --------------------------- | ------------------- |
| `scripts/run_official_eval.py` | 评测条数上限；**省略 = JSONL 全部非空行** | 省略=全量（旧默认曾是 `1`，已改） |
| `wrapper_evaluation_*.py`      | 同上；`None`/省略 = 不切片，评文件内全部   | 省略=全量               |


**固化约定**：

1. 报官方 Overall Accuracy / 写复盘数字前，确认日志里有 `Official eval scope: 全量 (N)` 或 `N/N`，且 `Total instances: N` 与 pred 条数一致。
2. val28 / hard40 / Flash200：**必须**让 `N` 等于集合大小（28 / ~40 / 200），不要漏写后只评 1 条还当全量。
3. 仅调试连通性时才用 `--limit 1`；此时报告准确率**不得**当作集合成绩。
4. 直接调官方 wrapper 时同样：`--limit 1` 只评 1 题；全量请**不要传** `--limit`，或显式传集合大小。



## 4. Flash（现行：flash200）

题面须 **schema ⊕ input**（仅 schema 无 `issue_sql`）：

```bash
python scripts/check_sol_alignment.py \
  --schema benchmark/baseline/data/flash_schema.jsonl \
  --input benchmark/baseline/data/flash/flash-00000-of-00001.jsonl \
  --sol benchmark/evaluation/flash_sol/bird-critic-1.0-flash_w_sol.jsonl \
  --report outputs/flash_align_report.json --require-pred-fields

python scripts/run_bird_critic.py \
  --schema benchmark/baseline/data/flash_schema.jsonl \
  --input benchmark/baseline/data/flash/flash-00000-of-00001.jsonl \
  --dialect postgresql --output outputs/flash200_pred.jsonl \
  --resume --workers 4 --mode diag+opt --force-batch
  # 默认 --isolate subprocess；沙箱 4 槽；LLM 见 config/agents.json

python scripts/merge_pred_with_sol.py \
  --pred outputs/flash200_pred.jsonl \
  --sol benchmark/evaluation/flash_sol/bird-critic-1.0-flash_w_sol.jsonl \
  --output outputs/flash200_eval_ready.jsonl --require-pred

# Flash 200 必须全量；省略 --limit
python scripts/run_official_eval.py --dialect postgresql --jsonl outputs/flash200_eval_ready.jsonl --num_threads 2
```

消融：`--mode diag_only|opt_only|diag+opt`。采样沙箱下 QEP 不硬否决；非 Efficiency 不因耗时硬否决（见 `docs/架构说明书.md`）。
